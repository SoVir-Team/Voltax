## Notes added after the run (by hand; the numbers above are unchanged)

- **Final audit verify: 401 "sign in again" is a harness fault, not a product fault.** The
  orchestrator signed its admin session in during seeding and left it idle for the whole run; the
  cloud's 60-minute idle limit (`SESSION_IDLE_MS`) then rightly refused it. The audit chain was
  verified under load instead: super admins called `POST /audit/verify` 55 times in the measured
  hour, all answered 200 (0 unexpected errors). The harness will sign in again before its final
  verify in later runs.
- **Slowest endpoint: `POST /audit/verify`** (p50 483 ms, max 2,038 ms, the run's maximum). It walks
  the whole chain, which grew to about 77,000 records in this run, so its cost grows with the log.
  Inside the gates, but production will need checkpoint-based (incremental) verification as the log
  grows. Recorded as a follow-up, not hidden.
- **Command acknowledgement:** p99 364 ms, max 2,681 ms; every command in the window was confirmed.
- **Earlier smoke findings now gone:** 3 diagnostics requests that got no hub answer in a pre-fix
  smoke run did not recur (0 unanswered over this hour, with hub-side traces on). Commands wrongly
  shown as refused (replay refusal bug) and slow owner notices (no SMTP pooling) were fixed in
  `55db509` and `a869081` before this run.
